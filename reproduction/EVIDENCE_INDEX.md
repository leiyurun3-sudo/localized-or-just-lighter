# Evidence and reproduction guide

Extract the supplement with its directory structure intact. Run `python reproduce.py` at the root for the headline point estimates (standard library). Use `python reproduce.py --ci` for the paired SAM bootstrap intervals (NumPy). For response sensitivity, run `python analysis/v20_mrc/reproduce_mrc.py --output rerun` with NumPy. Read its local README for definitions and output columns. These analyses use recorded scores. The root output reports the original five-setting SAM scan and the four-setting restriction at or below default (under `scales_at_or_below_default`). Each retained fraction uses the default gap on its own supported sources.

## Checks using the recorded trajectories and outputs

Run these commands from the extracted ZIP. Each analysis directory includes the input measurements or a reference to the shared scores, its implementation and the resulting source-level records. The supplementary section *Post Hoc Checks on Recorded Trajectories and Outputs* gives the estimands and denominators.

| Question | Command |
|---|---|
| At a control's attained directional CLIP, which native settings give lower background loss? | `python analysis/v21_operating_points/compare_points.py --points cpu/selectivity/operating_sources.csv --output rerun/points` |
| How does the result change at equal fractions of pixel change in the edit region? | `python analysis/v21_operating_points/compare_share.py --points cpu/selectivity/operating_sources.csv --output rerun/share` |
| How closely can two constant gains fit recorded SAM projections? | `python analysis/v21_constants/reproduce.py --out rerun/constants` |
| How does removing the above-default scale 1.25 change the estimate, its source sample and its response range? | `python analysis/v21_bounded/bounded_mrc.py --output rerun/bounded` for full and bounded first-crossing source comparisons. The root headline script prints both sets of estimates. |
| How does removing either interior scale between 0.25 and 1.00 change matched response and source coverage? | `python analysis/v21_bounded/bounded_thinning.py --output rerun/bounded_thinning` |
| What does a three-setting grid miss? How accurate is a held-out setting? | `python analysis/v21_grid/grid_check.py --output rerun/grid` |
| How do map alignment, smoothness and initial attenuation relate? | `python analysis/v21_map/analyze.py --from-records` |
| How well do predictions transfer across the recorded source cohorts? | `python analysis/v21_transfer/analyze.py` |

The map analysis uses NumPy and SciPy. Its aggregate results can be reproduced from the anonymous records in this ZIP. Re-extracting those records from pixel arrays requires the original maps and input images; the ZIP includes the extraction code. Bootstrap resampling, repeated-seed aggregation, overlap rules and fixed-state fits are specified locally. The held-out settings are archived generated outputs. The fitted gains were evaluated on recorded states.

## Components, settings and checksums

- **Source membership and seeds.** `SAM_scan/data/sources.csv` contains the 50 SAM source IDs, categories, seed and region sizes. The early score CSVs retain all 40 restoring IDs, seeds and arm identifiers. The selection manifest and historical exclusion rules are in the study archive; the supplement lists the selected sources and instructions. Preserve leading zeros in IDs.
- **Code, profiles and maps.** `SAM_scan/control/projection_control.py` contains the generation-time intervention with its upstream notice. `SAM_scan/data/protocol.json` records the upstream commit, model, grid, control digest, precision and tolerances. `SAM_scan/data/core_steps.csv` gives 26 active steps on 250 core projection jobs. The early study archive retains generator/evaluator code, step summaries and request-map arrays. The review ZIP supplies the map measurements and one four-cell profile in `evidence/example_rms.csv`. Full generator trees, dense maps, model tensors and per-step logs for all outputs are outside the ZIP.
- **Archived images and hashes.** `evidence/historical_native_coverage.csv` gives an expected PNG SHA-256 and native availability flag for every early output. `evidence/native_counts.csv` counts retrieved files by dataset, arm and seed. The six per-output score CSVs under `H/` include `expected_raw`, `expected_source` and `expected_mask` SHA-256 fields. The 1,964 rescored rows correspond to 1,960 distinct output digests, including four exact repeat checks. Recomputing an image metric requires its native output, source, evaluation mask, evaluator and weights.
- **Evaluation configuration.** `evidence/provenance.json` gives the three SAM archive digests and sizes, evaluation code and mask-manifest hashes, LPIPS backbone and calibration hashes, SAM CLIP ViT-B/32 asset hashes, CPU software versions and score-reproduction errors. The historical restoring evaluation used CLIP ViT-L/14. Two early metadata members were unavailable in the examined primary/scale archives: `runtime_base/results/evaluation_config.json` and `run/identity.json`. Historical model revision IDs and score definitions appear in the supplement. The scalar run reused the R91 tensor inventory. The R92 audit records matching tensor headers and lengths, a false revision-directory match and no full generator-weight payload digest.
- **Historical evidence.** `analysis/history/supp_history_recovered.json` preserves original archive member names, native REQ edit MAE and same-state attenuation on 80 trajectories, and the archived cohort-level interpolation. `analysis/history/supp_r89_matched_response.json` documents the separate within-source three-setting calculation. Human instruction-success ratings were not collected.
